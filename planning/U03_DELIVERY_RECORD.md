# U03 delivery — React functional parity and recovery

3 October 2026 · complete for the agreed local demonstrator migration scope.

The delivered React app preserves both scientific student journeys and adds the missing faculty, asset, calibration, mobile, bookings, map and safety tasks. Original source, geometry and design references remain available. The coverage ledger records deliberate composition changes and the boundary between interactive examples and actual institutional services.

## Delivered improvements

- Teaching plan with a six-pair rotation, source-labelled preparation snapshot and current resource shortfalls.
- Attendance correction with original/corrected values, required reason, actor/time history, saved drafts and stale-write refusal.
- Revision-aware assessment with paired illustrations, passage anchors, four criterion reviews, preview, publication freeze and links to actual React receipts.
- Asset passports with kit consequences, occupancy, location records and guarded movement history; separate calibration-reference and review workflow.
- Persistent fault/repair drafts, staged verification, immutable repair records, visible closed history and protected release after interrupted checks.
- Mobile typed-ID lookup, wrong-lab recovery, independent bookings and deferred-report retry. Compact Views menu works by keyboard and closes after navigation.
- React-linked optional 3D map using canonical geometry and a private-data-free equipment projection; plan/list remain usable when WebGL is unavailable.
- Always-reachable illustrative safety orientation and a delayed public-display snapshot demonstration.
- Recovery copies before reset and restore; restoration also retains the session being replaced. Failed recovery writes refuse reset. Old/incompatible records remain exportable and old schema-1 sessions remain readable.
- Scientific capture/claim freeze after receipt, fixed journey navigation with focus spacing, and wrapping long evidence-source status labels on narrow screens.
